日期：2026-08-29  
状态：**第一版已完成**（M0 / M5a / M5b / M3）。产品界面视觉见 [`2026-08-29-kawaii-minimal-design.md`](./2026-08-29-kawaii-minimal-design.md)。M5c 证据和结构 **已取消，不做**。  
里程碑：[`2026-08-29-汇报不返工-milestones.md`](./2026-08-29-汇报不返工-milestones.md)  
旧方案备查：[`2026-08-29-汇报不返工-design.md`](./2026-08-29-汇报不返工-design.md)（固定 8 页 / 表格算数 / 三问澄清）

## 1. 问题与目标

职场人做汇报时，真正耗时的不是排版，而是没说清领导要判断什么、材料散、做完被打回。

本版产品核心：

> 根据汇报背景和工作材料，先识别领导这次要判断的问题，用户确认主线后再出预览和可编辑 PPT。下载前验收能不能交。

不把业务漏斗或进度表当成每次必填。不为凑页数发明数字或空图。

成功标准（本版即停）：

- 粘贴、口述或从 Notion 导入材料后，能分析出核心问题、风险、下一步
- 用户能改主线再分析；最初背景默认收起，可用「重新生成背景」打开再改
- 预览后能验收：可提交 / 需要修改，并能复制交付消息
- 需要时导出可编辑 PPTX
- 数字不编造；领导没点名的缺量化只是建议

## 2. 范围

做：

- 创建：我最初的汇报背景（打字或语音）+ 工作对话/材料（粘贴或 Notion 导入）+ 可选时长
- Flash 产出 `ReportAnalysis`：标题、管理问题、意图、结论、发现、风险、行动、拍板事项
- 确认主线：默认只展示分析出的 7 项主线；最初背景和材料收起，点「重新生成背景」后再改、再分析
- 固定结构的网页预览：封面 / 核心结论 / 风险点 / 下一步与拍板
- 下载前代码验收 + Pro 语义验收；可复制交付消息
- 可选导出 PPTX
- 工作台视觉：Kawaii Minimal（奶油底、糖果色按钮/标签、轻回弹交互）

不做：

- 把漏斗或进度做成创建页必填表单
- 九种证据模块、漏斗四条件门禁、按意图换页结构（原 M5c）
- 自定义画布、多 Agent、账号体系
- 往 Notion 回写

## 3. 架构原则

```
材料 → ReportAnalysis → 用户确认 → DeckSpec → 网页预览 / 验收 / PPTX
```

禁止：材料 → LLM → PPTX（跳过确认和校验）。

分工：

- LLM Flash：从背景和材料里抽主线，不编造材料没有的数字
- LLM Pro：语义验收 + 交付消息
- TypeScript：Deck 组装、裸数字检查、点名指标门禁、PPT 渲染
- 用户：改主线、补材料、决定是否提交

## 4. 数据模型

```ts
type ReportIntent =
  | "result"
  | "progress"
  | "retrospective"
  | "decision"
  | "product_conversion";

interface ReportAnalysis {
  title: string;
  leaderQuestion: string;
  intent: ReportIntent;
  coreConclusion: string;
  keyFindings: string[];
  risks: string[];
  nextActions: string[];
  decisionAsk?: string;
  missingInformation: string[];
  excludedDetails: string[];
}
```

`intent` 本版只作确认页标签和封面副标题，**不**据此切换幻灯片结构。

`AuditReport`：

```ts
type AuditReport = {
  status: "ready" | "needs_revision";
  blockers: string[];
  suggestions: string[];
  likelyFollowups: string[];
  deliveryMessage: string;
};
```

阻塞：领导在汇报背景里点名了指标（转化率、故障率等）而材料没有对应数字；稿子里出现材料没有的数字；页数过少/过多；讲解时长超过要求 20%；PPTX 空文件。  
建议：领导没点名指标时的「缺量化」。

## 5. 用户流程

```text
创建（背景 + 材料）
  → 分析主线
  → 确认 / 改主线 / 补材料
  → 预览
  → 验收（可提交 / 需要修改）
  → 可选导出 PPT
```

向导：创建 → 确认主线 → 预览 → 验收。

### 5.1 创建

必填：我最初的汇报背景。支持打字和浏览器语音输入（中文）。  
选填：工作对话或材料、时长、连接 Notion 导入页面。

不出现：漏斗表单、必填进度。

测试材料按钮（也可从 `fixtures/audit/` 复制）：

| 按钮 | 预期 |
| --- | --- |
| 完整 demo | 可提交，可能建议缺量化 |
| 点名转化（应阻塞） | 需要修改 |
| 缺量化（建议） | 可提交，建议缺量化 |

### 5.2 确认主线

分析完成后默认只展示 7 项主线，最初的汇报背景和工作材料收起。点「重新生成背景」后可改背景（仍可语音）或再从 Notion 导入材料，然后重新分析。重新分析成功后背景再次收起。也可确认并预览。

用户每次改「汇报目的」（尤其是进度汇报 / 结果汇报）后，立即按新目的重写核心问题、结论、发现、风险和下一步，不只改标签。预览页标题随目的微调（例如进度用「当前进展」，结果用「核心结论」），页结构仍是封面 / 结论 / 风险 / 行动。

### 5.3 预览与验收

预览固定两页：封面 + 第二页把发现、风险、下一步、拍板尽量塞满。不限每页三句。最多 4 页。封面标题居中。

进入预览后自动验收。可提交则复制交付消息后再导出；有阻塞则先改主线或按意见重生成。导出 PPT 页数可选 1–4。

「按意见重生成」若识别到页数、封面、排版等 PPT 要求，按用户意见重排幻灯片并保留封面；若意见是结论、风险、主线，则先改主线再出 PPT。

## 6. Notion

- Public integration + OAuth。用户点「去授权」，在 Notion 勾选页面后返回本站
- Client ID / Secret 只在服务端环境变量，不让最终用户填写
- Access token 放 httpOnly cookie
- 导入正文带页面标题和来源链接
- 只读，不写回
- 上线时在 Notion 后台追加生产 Redirect URI，Vercel 写 `NOTION_REDIRECT_URI`

## 7. 生成与校验

Deck 只消费用户确认后的 `ReportAnalysis`。

- 标题从材料总结，8–16 字名词短语
- 禁止编造材料里没有的数字、国家、结论
- 风险点用「风险」表述，不用「缺口」
- 验收见第 4 节 `AuditReport`

## 8. 已取消（本版不做）

### M4 套设计风格

不换成品色板、字体层级、PPT 母版。现有 token 保持可用即可。

### M5c 证据和结构

不做：

- 九种 `EvidenceType` 与独立渲染器
- 漏斗四条件门禁
- 确认页「系统建议使用的证据」的增删改换
- 五套 `ReportIntent` 结构模板（正文 4–7 页按意图换版）
- Demo A 漏斗 / Demo B 非漏斗对照验收

这些曾作为后续档写过，现从范围中删除，避免和已交付产品冲突。

## 9. 明确不采用的做法

- 材料直接交给模型出 PPT，跳过确认和验收
- 创建页强迫用户填漏斗或进度
- 为了页数完整而编造数字或留空图表
- 把 Client ID / Secret 交给最终用户填写
