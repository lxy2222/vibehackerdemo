# 汇报不返工 — 分阶段目标

日期：2026-08-29  
原则：**第一版只要求能跑。** 当前产品定义见 [`2026-08-29-动态证据模块-design.md`](./2026-08-29-动态证据模块-design.md)。视觉风格并行调研，不在排版上打转。

```text
M0 能下载 PPTX     ← 已完成
M1 数字来自表格     ← 部分被模版优先路径替代
M2 澄清到生成闭环   ← 已被「确认主线」取代
M3 自动验收
M4 套你的设计风格
M5a 对话能分析     ← 已完成
M5b 连接 Notion     ← 下一档：从 Notion 拉材料
M5c 证据和结构     ← 原 M5b + 原 M5c，完整验收
```

## M0 · 第一版：能跑起来

**状态：已完成（2026-08-29）**

本地 `npm run dev`，打开页面即可下载 8 页 PPTX。缺数据版用于验证「资料未提供」布局。

**目标：** 本地打开页面，点一下，下载一份 8 页可编辑 PPTX。

做：

- 初始化 Next.js（App Router + TS + Tailwind）
- 色卡和中文字体写进主题常量（先不追求「好看」）
- 一份写死的 `DeckSpec`（内容可来自 demo 案例的结论，不必接模型）
- PptxGenJS 8 个渲染器的最小实现
- 一个极简页面：按钮「下载演示 PPT」

不做：上传、LLM、数据库、验收、精致 UI。

**验收：**

- `npm run dev` 能打开
- 下载的文件能用 WPS / PowerPoint 打开
- 中文不乱码，有至少一张原生图表，封面以外有演讲备注
- 无表格页可用写死的「资料未提供」占位（证明两条布局都能出）

这是唯一必须先完成的里程碑。后面都可以叠在这条链路上。

## M1 · 数字是算出来的

**目标：** demo CSV 进系统后，PPT 上的数字来自 Fact，不是写死文案。

做：

- 解析 `.csv` / `.xlsx` 和 `.txt` / `.md`
- Fact Engine（环比、渠道对比等第一版固定计算）
- `factRefs` 校验：引用必须存在
- 渲染时从 Fact 填数字
- 可用最简 API 或脚本跑通，页面能选「使用 fixtures/demo」

不做：列映射交互可以先按 demo CSV 的表头自动认；认不准再在 M2 补确认 UI。

**验收：**

- 用 `fixtures/demo/campaign-data.csv` 生成的 PPT，转化率/收入等与表格一致
- 不传表格时，KPI/趋势/对比为「资料未提供」，不出现编造数字

---

## M2 · 闭环能跑（产品主路径）

**目标：** 粘贴领导原话 → 最多 3 问 → 出大纲 → 生成 PPT。四个页面能走通，长得可以很朴素。

做：

- DeepSeek：Flash 做需求识别，Pro 做 DeckSpec
- `json_object` + Zod + 失败重试 1 次，thinking 关闭
- 四个功能页（创建 / 澄清 / 大纲 / 下载），样式保持可用即可
- 项目状态机 + 本地 SQLite（够用就行）
- 同步 `/generate`

不做：精致动效、品牌视觉、在线编辑 PPT。

**验收：**

- `fixtures/demo/leader-request.txt` + 纪要 + CSV，人工答 3 个澄清问题后能出 PPT
- 大约一分钟内返回（网络正常时）
- 模型结论里没有无法对应 Fact 的裸数字

---

## M3 · 验收能跑

**目标：** 下载前知道能不能交给领导，并复制交付消息。

做：

- 代码验收（8 页、factRefs、时长、文件非空、点名指标缺失则阻塞）
- Pro 语义验收 + 交付消息
- 验收页：可提交 / 需要修改

**验收：**

- 完整 demo：能给出交付消息
- 故意不传 CSV、且领导原话点名要看转化：出现阻塞
- 只缺表格、领导没点名具体指标：「缺量化」是建议不是阻塞

**目标：** 把你调研好的成品风格落到四个页面和 PPT 母版。

开始条件：你给到可执行的参考（截图、色板、字体、1–2 页示例）。在此之前 M0 的色卡只是占位。

## 和「第一版能跑」的关系

| 你要的状态 | 停在 |
| --- | --- |
| 自己能下到一份 PPT，证明技术链通 | **M0** |
| 数字可信，可以给朋友看数据没编 | M1 |
| 能用 demo 材料走完产品故事 | M2 |
| 能当比赛/演示闭环 | M3 |
| 看起来像成品 | M4 |
| 贴一段对话就能分析问题和改主线 | **M5a** |
| 从 Notion 选页面当汇报材料 | **M5b** |
| 证据推荐正确，不同意图出不同结构 | M5c |

建议开工顺序就是 M0 → M1 → M2。动态证据从 M5a 起：先保证对话能分析，再接 Notion 材料，最后优化证据和结构。视觉定了再进 M4，不必返工流水线。

## M5a · 对话能分析（先保证能跑）

**状态：已完成（2026-08-29）**  
**依据：** [`2026-08-29-动态证据模块-design.md`](./2026-08-29-动态证据模块-design.md)

**目标：** 发送一段对话后，系统能指出领导要判断的问题、风险点和下一步，用户能改主线再跑一遍。不填漏斗，不填进度表。这一档停住，也可以演示「我丢一段对话，它帮我把汇报问题理清」。

做：

- 创建页改成：「我最初的汇报背景」+ 一段工作对话/材料（大文本）。去掉必填进度和漏斗表单
- `ReportAnalysis` 先落地主线字段：`leaderQuestion`、`intent`、`coreConclusion`、`keyFindings`、`risks`、`nextActions`、`decisionAsk`、`missingInformation`
- Flash 分析这一段对话；确认页展示上述 7 项，可编辑后重新分析
- 用现有文字页（结论 / 问题 / 行动）出一份极简预览，证明链路通。不新做九种证据渲染器，不按五套意图换结构

不做：

- 漏斗四条件、证据替换、两套正式 Demo、新 PPT 版式
- 文件上传可以后放；这一档粘贴对话就够

**验收：**

- 粘贴一段真实对话（或随便一段工作沟通），大约一分钟内回到「确认主线」
- 能看到核心问题、风险点、下一步；数字不编造
- 改一句结论或补一句材料，能重新分析
- 创建页没有漏斗表单，也不要求填进度

## M5b · 连接 Notion（拉材料）

**状态：待实现**  
**依据：** [`2026-08-29-动态证据模块-design.md`](./2026-08-29-动态证据模块-design.md)

**目标：** 汇报材料不必只靠粘贴。用户连上 Notion 后，能选一篇（或几篇）页面，把正文拉进「工作对话或材料」，再走现有分析。这一档只做读，不写回 Notion。

做：

- 用 Notion Internal Integration：服务端读 `NOTION_API_KEY`，集成必须能访问用户勾选的页面
- 创建页增加「从 Notion 导入」：搜索/列出可访问页面，选中后拉取块内容，转成纯文本填进材料框
- 也支持粘贴 Notion 页面链接，解析 page id 后导入
- 导入后仍可编辑材料，再点「分析汇报主线」；分析链路不改
- 记下来源（页面标题 + URL），确认页能看到材料来自哪篇 Notion

不做：

- OAuth / 多账号 / 选整个 workspace 全量同步
- 往 Notion 回写汇报或生成 Notion 页
- 证据模块、漏斗门禁、新 PPT 结构

**验收：**

- 不连 Notion 时，纯粘贴路径和 M5a 一样能用
- 连上后能搜到集成已分享的页面，导入正文，分析出主线
- 粘贴一个已分享页面的链接也能导入
- 不把 Notion 里没有的数字编进分析
- Key 只在服务端，不进前端日志

---

## M5c · 证据和结构（优化输出）

**状态：待实现**  
**依据：** [`2026-08-29-动态证据模块-design.md`](./2026-08-29-动态证据模块-design.md)

**目标：** 原「证据选得对」+「结构出得对」。建议 1–3 个证据模块；不同汇报目的生成不同结构；两套 Demo 能对照；不为凑页数出空图。完整验收在这一档。

做：

- 补齐九种 `EvidenceType` payload 与漏斗四条件门禁
- 确认页增加「系统建议使用的证据」：类型、原因、提取结果；可确认 / 编辑 / 删除 / 换类型
- 五套 `ReportIntent` 结构模板，正文 4–7 页，禁止 pad 空页
- 九种证据的独立预览组件 + PPTX 渲染器
- Demo A：模板点击 → 使用 → 生成 Design（漏斗）
- Demo B：跨国家复用与交付效率（影响指标 + 前后对比 + 里程碑，全程无漏斗）

**验收：** 沿用动态证据 spec 第 11 节全清单。
